Kazual-512

Полная спецификация блочного шифра: блок 512 бит, ключ 512 бит, 5 тяжёлых раундов. Каркас — схема Лай–Мэсси; раундовая функция F — необратимый SPN с ключезависимыми таблицами и ARX-предтактом; пол-раунд H — связка «ортоморфизм в GF(2¹⁶) → несущая ARX → полный веер MDS 64×64»; расписание ключей — двутактная обобщённая сеть Фейстеля Type-2 с самоизменяющимися таблицами. Внешних криптографических примитивов нет: собственная сжимающая функция ГОРН-1024 собрана из тех же кирпичей, что и шифр. Семью дополняет Kazual-64 (§13) — учебная версия того же алгоритма в размерах, пригодных для счёта вручную и даже на бумаге; для защиты данных предназначен только Kazual-512.

Все заявленные свойства вычислены запуском кода. Эталонная однофайловая реализация kazual-512.py воспроизводит алгоритм побитово: тестовые векторы (§14), трассу Kazual-64 вплоть до внутренних стадий (§13) и ключевой подмножество проверок — режим --selftest (~15 с). Расширенные измерения (750 трейлов, полные переборы) выполнены исходным пакетом kazual/results.py и зафиксированы в kazual/results.json, из которого собран этот документ.

Дисклеймер. Это экспериментальная учебная конструкция, собранная, чтобы показать, как сочетаются каркас Лай–Мэсси, SPN, APN-подстановки, динамические Cauchy-MDS, смешанная алгебра (GF(2⁸) / GF(2¹⁶) / Z₂⁶⁴) и GFN-расписание ключей. Она не проходила независимого криптоанализа, не имеет формального доказательства стойкости и не предназначена для защиты реальных данных. Ниже — инженерный проект с явными обоснованиями, разделением «доказано / измерено / предположено» и честно перечисленными пробелами (§15).

§1Философия: тяжёлый раунд и «полезная странность»

Ограничение задано так: раундов мало, зато каждый максимально тяжёлый, и всё это не должно ломать параллелизм. Отсюда два правила, которым подчинён весь проект.

Правило 1. Сложность должна конвертироваться в биты

Каждое усложнение обязано пересчитываться в измеримую величину: дифференциальную равномерность δ, нелинейность NL, ветвевое число, число активных S-box’ов, алгебраическую степень, энтропию ключа, ширину SIMD-дорожки. Если выгода не измеряется — решение не принимается.

Правило 2. «Полезная странность» вместо странности вообще

Экзотика допускается только та, которая ломает чьё-то удобное для атаки предположение: что таблицы одинаковы для всех ключей, что линейный слой фиксирован, что в раунде одна алгебра, что хеш — это чёрный ящик из учебника. Плата за это — сложность понимания; она в списке приоритетов последняя.

§3Три алгебры и статическое ядро

Kazual-512 намеренно живёт сразу в трёх несовместимых алгебраических структурах. XOR-линейность GF(2ⁿ) даёт доказуемые ветвевые числа; переносы в Z₂⁶⁴ дают алгебраическую степень, недостижимую ни для какой XOR-схемы; GF(2¹⁶) даёт ортоморфизмы, нужные каркасу Лай–Мэсси. Алгебраическая атака, работающая в одной из них, разваливается о две другие.

Ловушка, в которую легко попасть. Полином 0x11B неприводим, но не примитивен: порядок элемента 2 в нём равен 51, а не 255 (проверено перебором). Таблицы log/alog, построенные «умножением на 2», заполняют только подгруппу из 51 элемента и дают неверные произведения. Умножение a ⊗ b = alog[(log[a] + log[b]) mod (2ⁿ − 1)], при a = 0 или b = 0 результат 0. Обратный элемент a⁻¹ = alog[(2ⁿ − 1 − log[a]) mod (2ⁿ − 1)]. Умножение по модулю 2⁶⁴ обратимо только для нечётных множителей — поэтому КУЗНИЦА выдаёт множители Несущей через x | 1.

Все значения вычислены полным перебором (kazual/sbox.py), а не взяты из литературы.

Что это даёт

  • δ = 2 вместо 4 → вероятность дифференциального перехода падает с 2⁻⁶ до 2⁻⁷ на каждый активный APN S-box. При измеренных ≥93 активных на вызов F разница с AES-подобной конструкцией составляет порядки.
  • NL = 112 у всех трёх → линейная стойкость не хуже, чем с биективными S-box’ами, то есть выигрыш в дифференциальной стойкости получен бесплатно.
  • Степени 2 / 4 / 7: чистая квадратичная x³ обнуляется на дифференциалах 3-го порядка, поэтому в каждом такте примерно треть позиций получает S₃ степени 7 — алгебраическая степень композиции насыщается за 2–3 такта (измерено на микро-инстанции: 4 → 14 из 16, §11.4).
  • Небиективность — фича: образ S₁ и S₂ — по 86 значений из 256, то есть каждая такая позиция безвозвратно теряет ≈1.57 бита. Отсюда необратимость F (§7.4).
  • Разная bitslice-цена: 28 / 154 / 246 AND-гейтов с общими подтермами. Квадратичная Gold-функция почти бесплатна: x³ = x ⊗ x², возведение в квадрат в GF(2⁸) линейно (чистые XOR), поэтому вся нелинейность укладывается в 28 попарных произведений xi·xj — ровно C(8,2) = 28. Две трети позиций каждого такта занимают именно такие подстановки.

3.3 Cauchy-MDS и её динамическая форма

Базовая матрица Коши размера n над GF(2⁸):

C[a][b] = ( a ⊕ (n + b) )⁻¹ a, b = 0 … n−1 # a пробегает [0, n), аргумент n + b пробегает [n, 2n): # старшие биты различаются, поэтому a ⊕ (n+b) ≠ 0 всегда

Все a различны, все n + b различны, ни одна сумма не равна нулю — значит по формуле определителя Коши любая квадратная подматрица невырождена. Отсюда матрица MDS и ветвевое число B(C) = n + 1:

B(M) = minx≠0 ( wt(x) + wt(M·x) ) = n + 1 n = 8 (ветвь расписания) → B = 9 n = 32 (такт F) → B = 33 n = 16 (микшер ГОРНа) → B = 17 n = 64 (Веер, GFN)→ B = 65

Динамическая форма: M = Pπ · C · Pρ

Ключ задаёт две перестановки π и ρ множества {0 … n−1}, и матрица раунда собирается как

M[i][j] = ( π(i) ⊕ (n + ρ(j)) )⁻¹ = C[ π(i) ][ ρ(j) ]

Три следствия, каждое из которых проверено:

  • Ветвевое число не зависит от ключа. M — матрица Коши с координатами x_i = π(i) (все различны, из [0,n)) и y_j = n + ρ(j) (все различны, из [n,2n)); x_i ⊕ y_j ∈ [n, 2n), то есть никогда не ноль. Значит любая квадратная подматрица невырождена, M — MDS и B(M) = n + 1 для любого ключа. Это то, что позволяет иметь ключезависимый линейный слой, не теряя ни бита доказуемой стойкости.
  • Обратная матрица бесплатна. Из M = Pπ C Pρ следует
    M⁻¹ = Pρ⁻¹ · C⁻¹ · Pπ⁻¹, то есть M⁻¹[j][i] = C⁻¹[ ρ(j) ][ π(i) ]
    C⁻¹ — одна фиксированная матрица размера n, зашитая в реализацию. Обратный ход требует только переставить индексы: ни обращения матриц на ключ, ни второй копии памяти. Именно поэтому Веер 64×64 в пол-раунде (§8) не стоит ничего при дешифровании.
  • Множество значений фиксировано. Возможные элементы — это { (n+t)⁻¹ : t = 0 … n−1 }, ровно n штук, и они не зависят ни от π, ни от ρ (проверено: для n = 8 / 32 / 64 число различных значений равно 8 / 32 / 64 при любых перестановках). От ключа зависит только расположение. Практический смысл: нужно n таблиц умножения по 256 байт (8 КБ для n = 32 и 16 КБ для n = 64), общих на все ключи, — кэш-профиль, bitslice-реализация и площадь в аппаратуре не зависят от ключа.
Проверено на 9 случайных наборах (π, ρ) для n = 8, 32, 64: все подматрицы до 2×2 невырождены, ветвевое число равно n+1, нулевых элементов нет, M · M⁻¹ = I при M⁻¹, собранной перестановкой индексов фиксированной C⁻¹. Ошибок 0.

Побочный бонус. Строка динамической MDS — это перестановка одного и того же набора из n констант, а столбец — перестановка того же набора. Поэтому слой «умножение на MDS» реализуется как n независимых XOR-сумм по n таблицам, без единого ветвления и без ключезависимых адресов памяти: ключ попадает только в таблицу индексов размером n² байт.

3.5 Ортоморфизмы в GF(2¹⁶)

Ортоморфизм — перестановка σ, для которой x ↦ σ(x) ⊕ x тоже перестановка. В схеме Лай–Мэсси он обязателен (§6). Берём аффинную σ в GF(2¹⁶):

σ(x) = a ⊗ x ⊕ b, условие: a ∉ {0, 1} σ(x) ⊕ x = (a ⊕ 1) ⊗ x ⊕ b — перестановка ⇔ a ⊕ 1 ≠ 0 ⇔ a ≠ 1 ✓

Нюанс, который часто путают. В циклической группе чётного порядка (Z₂¹⁶ у IDEA — сложение по модулю 2¹⁶) ортоморфизмов не существует, поэтому IDEA приходится использовать «почти ортоморфизмы». В XOR-группе Z₂¹⁶ (элементарная абелева 2-группа ранга 16) ортоморфизмы есть — например, умножение на любой a ∉ {0,1}. Это одна из причин, по которой Kazual-512 работает в XOR-группе, а арифметику по модулю 2ⁿ использует только там, где нужны переносы (Несущая, Заслонка).

Константы кросс-диффузии выводятся из ГОРНа с проверкой первообразности (порядок = 65535 = 3·5·17·257 проверяется по всем простым делителям):

(M₁, M₂) = 0x3423, 0x581D порядок M₁ = 65535 ✓ порядок M₂ = 65535 ✓ M₁ ⊗ M₂ = 0x066F # вывод: два первых байта ГОРН(msg="", tag="Kazual-512/H-CROSS/0") с установленным # в 1 младшим битом (нечётность); при непрохождении проверки первообразности # счётчик домена # увеличивается, пока оба элемента не станут первообразными (порядок 65535)

Первообразность M₁ и M₂ означает, что умножение на них перемешивает все 16 бит чанка: один бит входа расходится по всему чанку. Произведение M₁ ⊗ M₂ = 0x066F — единственное запрещённое значение для детерминанта стадии A (§8.1).

Kazual-512 не использует ни одного внешнего криптографического примитива. Всё, для чего обычно берут готовый хеш — вывод констант, предобработка ключа, расширение сидов КУЗНИЦЫ, — делает собственная функция ГОРН. Она собрана из тех же кирпичей, что и сам шифр (инверсия в GF(2⁸), Cauchy-MDS, ARX), и спроектирована «широкой и мелкой»: вместо одной длинной последовательной цепочки — 8 раундов по четыре коротких стадии при ширине 128 байт.

5.3 Почему это «полезная странность», а не усложнение

  • Нечего предвычислять. Линейные оболочки, таблицы пересечений, алгебраические системы — всё, что атакующий мог бы построить один раз и переиспользовать для разных ключей, — здесь существует в 2⁵¹² вариантах. Это прямое следствие того, что π, ρ и φ ключезависимы.
  • Скользящие (slide) атаки теряют опору. Даже если бы два раунда имели одинаковые подключи, их таблицы различаются: π, ρ, φ, маски и параметры Несущей берутся из разных выходов расписания.
  • Структурные атаки на фиксированный линейный слой невозможны. В обычном SPN матрица известна, и для неё можно заранее найти «удобные» подпространства (инвариантные подпространства, атаки на частичную диффузию). Здесь матрица — элемент множества из (32!)² ≈ 2¹⁶⁸ вариантов на такт, причём все они имеют одно и то же ветвевое число: худший случай не наступает, но и «удобных» матриц атакующий выбрать не может.
  • Цена — ноль по стойкости. Это ключевой пункт: δ, NL, ветвевое число, счёт активных S-box’ов, необратимость F, биективность H — всё доказуемо не зависит от того, какие именно таблицы выдала КУЗНИЦА (§5.1, §3.3).
  • Цена по памяти — заметна и названа честно: 223 КБ динамических таблиц на ключ в табличной реализации. Это плата за отсутствие ветвлений; в bitslice-реализации (§12.3) раскрывать таблицы не нужно вовсе.

§6Каркас Лай–Мэсси и пять закрытых дыр

Канон схемы Лай–Мэсси: из разности половин Δ = L ⊕ R раундовая функция делает T, и один и тот же T прибавляется к обеим половинам. Отсюда главное преимущество перед Фейстелем (обе половины меняются каждый раунд) и главная дыра (разность инвариантна).

Канон (без модификаций)

(L′₀, R′₀) = H(L₀, R₀) для i = 0 … r−1: T_i = F(L′_i ⊕ R′_i, K_i) # F НЕ обязана быть обратимой (L′,R′) = H(L′_i ⊕ T_i, R′_i ⊕ T_i) C = (L′_r, R′_r)

Почему это обратимо без F⁻¹. При дешифровании мы сначала применяем H⁻¹ и получаем пару (L⊕T, R⊕T). Её разность равна L ⊕ R — T сокращается! Значит, T = F(L⊕R, K) вычисляется заново, и половины восстанавливаются одним XOR. Требуется обратимость только у H. Именно это позволяет взять необратимую F с APN-подстановками.

§8H: пол-раунд «ортоморфизм → несущая → веер»

H — единственная часть шифра, от которой требуется обратимость: каркас Лай–Мэсси инвертирует F пересчётом, а H — по-настоящему. H составлен из трёх стадий, каждая из которых отвечает за свой тип перемешивания и каждая из которых проверяема по отдельности.

8.1 Стадия A: ортоморфизм — с доказательством

Стадия A работает на 32 чанках по 16 бит независимо (16 пар «L-чанк, R-чанк»), поэтому её свойства сводятся к свойствам одной пары. Линейная часть пары (L[c], R[c]) → (u[c], v[c]):

u = a ⊗ L ⊕ M₁ ⊗ R v = M₂a ⊗ L ⊕ (a′ ⊕ M₂M₁) ⊗ R ⎡ a M₁ ⎤ A = ⎣ M₂a a′ ⊕ M₂M₁ ⎦ det A = a ⊗ a′ ⊕ M₁ ⊗ M₂ ⊗ a = a ⊗ a′ A ⊕ id: ⎡ a⊕1 M₁ ⎤ ⎣ M₂a a′ ⊕ M₂M₁ ⊕ 1 ⎦ det(A ⊕ id) = (a⊕1) ⊗ (a′⊕1) ⊕ M₁ ⊗ M₂
Утверждение. Стадия A пол-раунда является (i) биекцией 512-битного пространства ⇔ a[c] ≠ 0 и a′[c] ≠ 0 для всех c; (ii) ортоморфизмом всей 512-битной XOR-группы (то есть x ↦ A(x) ⊕ x — перестановка) ⇔ дополнительно (a[c]⊕1) ⊗ (a′[c]⊕1) ≠ M₁ ⊗ M₂ для всех c. Оба условия — про 2×2 матрицу над GF(2¹⁶): она обратима тогда и только тогда, когда её определитель ненулевой. Стадия A действует одинаково и независимо на всех 16 парах чанков, поэтому достаточно выполнить условие для каждой пары.

Обе формулы определителей сверены с прямым вычислением определителя 2×2 матрицы по Гауссу на 3000 случайных парах (a, a′): расхождений 0 и 0 соответственно. Единственное запрещённое значение произведения (a⊕1)(a′⊕1) равно M₁ ⊗ M₂ = 0x066F; КУЗНИЦА отбраковывает a′, попадающие в него (ожидаемая частота 2⁻¹⁶, стоимость — одно лишнее чтение на 65536 пол-раундовых наборов).

Кросс-члены M₁ ⊗ R и M₂ ⊗ u — то, что отличает Kazual-512 от канонического пол-раунда: каждая половина получает и собственный ортоморфизм, и вклад другой половины. M₁ и M₂ первообразны (порядок 65535), поэтому один бит входа расходится по всем 16 битам чанка. Треугольная структура (u входит в v) сохраняет обратимость без обращения матриц.

8.2 Стадия C: Несущая

Та же Несущая, что и в Предтакте F (§7.2), но на полном состоянии: 8 слов по 64 бита, 4 фазы по 4 независимые пары — то есть 4-дорожечный SIMD внутри пол-раунда. Роль стадии — внести переносную нелинейность туда, где иначе остались бы только линейные по XOR операции. Без неё пол-раунд был бы «XOR-линейным с точностью до F», и любой линейный аппарат, построенный поверх A и B, переносился бы через H без потерь.

Порядок A → C → B выбран не случайно: последней стоит XOR-линейная MDS. Только так утверждение «вес Δz = 1 ⇒ вес Δ′ = 32» (§8.3) остаётся строгим — стадии A и C суть биекции, они сохраняют ненулевую разницу, но не сохраняют её вес, а Веер уже доводит вес до максимума и делает это доказуемо.

8.3 Стадия B: Веер и свойство Δ′

Веер — динамическая Cauchy-MDS размера 64×64 над GF(2⁸), применённая ко всему состоянию пол-раунда. Выход устроен как «проекция и сумма»:

t = M · z ; p = t[0…31] ; q = t[32…63] ; H(z) = (p ⊕ q, p) следствия: • стек [p; p⊕q] = [M_верх; M_низ] = M — значит H биективна тогда и только тогда, когда M обратима, а Cauchy-MDS обратима всегда (§3.3); • wt(t) ≥ 65 − wt(z) — ветвевое число 65 при ЛЮБОМ ключе; • Δ′ = u_out ⊕ v_out = q = M_низ · z — новая разница половин есть проекция НИЖНЕЙ половины Веера.

У матрицы Коши нет нулевых элементов (это обратные величины), поэтому ни один столбец M_низ не содержит нуля, и любая её 32×32 подматрица невырождена (это подматрица Cauchy-MDS). Отсюда два строгих следствия:

  • Δ′ ≠ 0 ⇔ Δz ≠ 0. Разница половин не может «схлопнуться» в ноль: дыра №1 каркаса закрыта не эвристически, а алгебраически.
  • wt(Δz) = 1 ⇒ wt(Δ′) = 32 (полный вес). Самый опасный для атакующего случай — однобайтовая разница — автоматически превращается в полновесную разницу на входе следующего F.

Ветвевое число самого Веера измерено как 65 (теоретически 65). Практический смысл: разница, входящая в F, имеет вес 31 из 32 байт в минимуме и 31.9 в среднем по всем пяти раундам.

§9Расписание ключей: двутактная GFN Type-2

Расписание должно одновременно: (1) дать полную лавину по ключу за 1–2 раунда, (2) быть односторонним, (3) не терять энтропию ключа, (4) не иметь повторяющихся раундов. Пункты (2) и (3) противоречат друг другу напрямую: потеря информации уменьшает энтропию. Разрешение — разделить их по разным узлам: односторонность обеспечивает ГОРН на входе, сохранение энтропии — доказуемо биективная двутактная GFN после него.

9.2 Почему двутактность: доказательство биективности

Обычный Type-2 раунд сам по себе обратим даже с необратимой ветвевой функцией: чётная ветвь сохраняется в состоянии, поэтому f(br[2j]) можно пересчитать и вычесть. Но если таблицы раунда брать из того же регистра, который этот раунд преобразует, обратимость теряется — и вместе с ней теряется энтропия ключа. Двутактность решает проблему в одну строку:

прямой ход: X₁ = G_X(Y) ; Y₁ = X ⊕ X₁ # G_X — Type-2 раунд с таблицами из X обратный ход: X = Y₁ ⊕ X₁ # сначала восстанавливается ВЕДУЩИЙ регистр Y = G_X⁻¹(X₁) # таблицы теперь известны — ведомый тоже
Утверждение. Отображение (X, Y) ↦ (G_X(Y) ⊕ RC, X ⊕ G_X(Y) ⊕ RC) биективно, если G_X биективна по Y при каждом фиксированном X. Доказательство: обратный ход выше однозначен — X восстанавливается одним XOR из известного результата, после чего таблицы Θ = TableGen(X) становятся известны и G_X обращается. Осталось заметить, что G_X — это Type-2 раунд: чётные ветви проходят через него нетронутыми (ветвевая функция только прибавляется к нечётным), поэтому необратимость S-box’ов не мешает: G_X⁻¹ вычисляется пересчётом ветвевой функции вперёд. Значит вся Стадия 1 — композиция биекций, Z ↦ material инъективна, и все 512 бит ключа доходят до подключей без потерь.

Замечание о формулировке: необратимость ветвевых S-box’ов не делает расписание односторонним — в фейстелевской структуре вход ветвевой функции всегда остаётся доступным, поэтому «одностороннее расписание на необратимых S-box’ах» — распространённая ошибка рассуждения. Односторонность в Kazual-512 обеспечивается Стадией 0 (ГОРН — сжимающая функция 512→512 бит, стойкость к прообразу ≈ 2⁵¹²), а сохранение энтропии — Стадией 1. Эти два свойства разнесены по разным узлам и не мешают друг другу.

Что даёт самоизменяемость таблиц: • раунд r и раунд r′ не совпадают даже при одинаковом состоянии ветвей — Θ_r зависит от X, который меняется каждый раунд ⇒ скользящие атаки на расписание не имеют опоры; • related-key различие меняет не только данные, но и САМИ линейные оболочки расписания: матрицы MDS у двух родственных ключей разные, поэтому «общая» related-key характеристика строится сразу по двум разным наборам таблиц; • цена: 140288 операций на ключ, один раз на срок жизни ключа.

11.2 Что доказано, а не измерено

  1. Динамическая Cauchy-MDS есть MDS при любом ключе. Координаты x_i = π(i) ∈ [0,n) и y_j = n + ρ(j) ∈ [n,2n) попарно различны, x_i ⊕ y_j ∈ [n,2n) ≠ 0 ⇒ по формуле определителя Коши любая квадратная подматрица невырождена ⇒ ветвевое число n+1.
  2. M⁻¹ = Pρ⁻¹ C⁻¹ Pπ⁻¹. Обратная матрица — фиксированная C⁻¹ с переставленными индексами: ни обращения матриц на ключ, ни второй копии памяти.
  3. Множество значений динамической MDS не зависит от ключа — это {(n+t)⁻¹ : t < n}.
  4. Аффинные маски сохраняют δ и NL точно (аффинная эквивалентность) и сохраняют «ноль/не-ноль» (A ≠ 0), поэтому не меняют счёт активных S-box’ов.
  5. φ — перестановка фиксированного мультимножества ⇒ числа позиций с δ = 2 и δ = 4 и граница образа F одинаковы для всех ключей.
  6. act₁ + act₂ + act₃ ≥ 34 для любого вызова F при любом ключе; отсюда p ≤ (2⁻⁶)³⁴ = 2⁻²⁰⁴.
  7. Стадия A — биекция ⇔ a, a′ ≠ 0; ортоморфизм ⇔ (a⊕1)(a′⊕1) ≠ M₁M₂. det A = a·a′, det(A⊕id) = (a⊕1)(a′⊕1) ⊕ M₁M₂ — обе формулы сверены с прямым вычислением определителя на 3000 парах.
  8. H — биекция (композиция биекций A, C, B), и Δ′ = Mниз·z, где у Mниз нет нулевых элементов и все 32×32 подматрицы невырождены ⇒ Δ′ ≠ 0 ⇔ Δz ≠ 0 и wt(Δz) = 1 ⇒ wt(Δ′) = n.
  9. Несущая и Заслонка биективны при любых параметрах (треугольность подшага; для Заслонки k₁, k₂ могут быть любыми).
  10. Стадия 1 расписания — композиция биекций ⇒ Z ↦ material инъективна ⇒ энтропия ключа не теряется (§9.2).
  11. Внутренняя перестановка ГОРНа биективна (все четыре стадии обратимы), ранг свёртки ровно 512 ⇒ губка корректна.
  12. Генерация КУЗНИЦЫ ровно равномерна: код Лемера (смещение ≤ 2⁻⁹⁶), отбраковка (смещение 0), x|1 (смещение 0).

11.5 Related-key: почему запаса больше, чем в линейной модели

Классическая related-key оценка считаетTrail по расписанию как по линейной схеме с фиксированными таблицами. В Kazual-512 это не так: таблицы раунда расписания Θ_r вырабатываются из ведущего регистра X, поэтому различие ключей меняет сами линейные оболочки.

Пусть K и K* различаются в одном бите. 1. Z = ГОРН(K) и Z* = ГОРН(K*) различаются в ~256 битах из 512 (SAC 256.2) — уже на входе GFN нет «одного активного байта», с которого можно было бы строить трейл. 2. X₀ = Z и X₀* = Z* ⇒ Θ₀ и Θ₀* различны ⇒ матрицы MDS₆₄ у двух ключей РАЗНЫЕ. Общая related-key характеристика должна быть одновременно трейлом для двух разных линейных систем — вероятность перемножается. 3. Линейная часть: полная MDS 64×64 с ветвевым числом 65 ⇒ любое ненулевое различие активирует ≥ 65 байт за два раунда ⇒ p ≤ (2⁻⁷)^65 = 2⁻⁴⁵⁵ (оценка СВЕРХУ, без учёта пункта 2). 4. Измерено: ≥ 126 байт из 128 различаются в КАЖДОМ из 32 выходов расписания.

Пункт 2 — содержательное усиление: он означает, что стандартная related-key модель (одна и та же функция раунда для всех ключей) к этому расписанию неприменима, и любая related-key атака обязана либо восстановить различие Θ (что стоит как минимум восстановления X, то есть полного ключа), либо работать с двумя несвязанными линейными системами.

11.8 Два потолка стойкости — их нельзя смешивать

Восстановление ключа стоит 2⁵¹² (перебор; расписание инъективно, §9.2, поэтому эффективное пространство ключей не меньше 2⁵¹¹·³ даже с учётом сжатия ГОРНом). Неотличимость от случайной перестановки ограничена размером блока: 2²⁵⁶ (birthday bound). Заявляемый уровень шифра принято брать по минимуму — 256 бит.

Важно, что это не слабость: столько же приписывают AES-256, чей потолок неотличимости и вовсе 2⁶⁴. Практический смысл большого блока обратный — лимит данных на один ключ: у Kazual-512 это ~2²⁵⁶ блоков (2²⁵⁹ байт), тогда как отраслевые ограничения для AES в GCM — 2³² блоков (256 ГБ) на ключ. 512-битный ключ при этом не «лишний»: он поднимает перебор до 2⁵¹², даёт запас в related-key модели (§11.5) и питает КУЗНИЦУ — на 6928 байт динамических таблиц расходуется 11 свежих сидов по 512 бит (5 для F, 6 для H), каждый из собственного выхода расписания.

Почему разделитель не превращается в атаку на ключ. Разделитель на 2²⁵⁶ запросов отличает шифр от случайной перестановки, но сам по себе не даёт ключа: чтобы превратить его в атаку, нужно связать наблюдение с ключом, а все структуры, через которые это можно было бы сделать (линейный слой, назначение S-box’ов, аффинные маски), у каждого ключа свои. Формально это не доказано (§15.3), но конструктивно «бесплатного» прохода от разделителя к ключу в схеме нет.

Отсюда: наивная реализация Kazual-512 медленнее AES-NI на два-три порядка, оптимизированная — примерно в 50–150 раз, и лишь в 2–6 раз медленнее табличного AES без аппаратного ускорения. Разрыв с AES-NI неустраним: у AES есть выделенные инструкции, которых у Kazual нет. Это осознанная цена за 512-битный блок, полную MDS 32×32 и 64×64, APN-подстановки, три алгебры и ключезависимые таблицы — за всё то, что покупает 5 раундов вместо 14 и запас по дифференциальной стойкости на сотни порядков.

Оценка площади в железе (грубо, по вентилям): одно умножение на константу в GF(2⁸) ≈ 20–30 XOR; Веер 64×64 ≈ 4096 умножений ≈ 100K вентилей на пол-раунд, 6 пол-раундов ≈ 600K; MDS 32×32 ≈ 25K на такт, 15 тактов ≈ 375K; S-box’ы: 480 экземпляров, но в bitslice это 28/154/246 AND-гейтов на позицию, то есть ≈100K. Итого порядка 10⁶ GE против ~5–30K GE у AES-128. Поправка в пользу Kazual: чтобы получить 512-битный блок на AES, нужны 4 параллельных ядра (×4 площади) плюс собственное расписание, так что разрыв на бит датапата — примерно два порядка, а не три.

12.3 Откуда берётся ускорение

  • SIMD по состоянию. 32 S-box’а независимы, 32 строки MDS независимы, 64 строки Веера независимы, 128 байт Σ-слоя ГОРНа независимы. Половина блока = 256 бит = ровно один регистр AVX-512; весь блок = 512 бит = один регистр AVX-512. pshufb-таблицы покрывают S-слой (~6 инструкций на такт), CLMUL — умножения в GF.
  • Динамическая MDS не стоит скорости. Ключ попадает только в таблицу индексов n² байт; значения — фиксированный набор из n констант (§3.3). Поэтому горячий цикл — это n² обращений к n общим таблицам и n·(n−1) XOR, без единого ключезависимого адреса и без ветвлений.
  • Обратный Веер бесплатен. M⁻¹ собирается перестановкой индексов фиксированной C⁻¹: дешифрование стоит столько же, сколько шифрование (0.62 мс против 0.58 мс в оптимизированном эталоне).
  • Bitslice и дешёвые квадратичные APN. 28 AND-гейтов у S₁ против 246 у инверсной подстановки и 154 у Kasami: x³ = x ⊗ x², а возведение в квадрат в GF(2⁸) — линейная операция (чистые XOR), поэтому вся нелинейность сводится к 28 попарным произведениям. Две трети позиций каждого такта занимают именно такие подстановки. Отсюда же — дешёвое маскирование.
  • CLMUL для GF(2¹⁶). Умножение в поле характеристики 2 — одна pclmulqdq + приведение. Это снимает единственную большую таблицу проекта (log/alog 256 КБ) и заодно убирает кэш-канал в стадии A.
  • Межблочный параллелизм. В режимах CTR/ECB/GCM блоки независимы → линейное масштабирование на любое число ядер и на GPU без изменения алгоритма.
  • Конвейер. Структура полностью регулярная: 5 одинаковых F и 6 одинаковых H. Критический путь короткий по числу разных узлов, конвейер даёт 1 блок за такт после заполнения.
  • ГОРН как широкий, а не длинный. 8 раундов по 4 стадии при ширине 128 байт вместо 80 последовательных шагов: глубина схемы — 32 коротких уровня против 80 тяжёлых, причём каждый уровень распадается на 128 / 8 / 16 независимых дорожек. На подготовку ключа уходит 385 таких перестановок на ключ (391 вместе с одноразовым выводом глобальных констант), и все они считаются до начала шифрования.
  • Реализовано в эталонной реализации (kazual-512.py). Одиночный путь без зависимостей: MDS-слои — колоночные big-int таблицы (⊗ линеен по второму аргументу ⇒ таблица из 256 слов собирается из 8 базисных; применение — 2n операций вместо n²), стадии Μ и Ρ ГОРНа слиты в один проход по 1024-битному слову (поворот лейн — один сдвиг), впитывание губки — целочисленный XOR. Пакетный путь: S-слой — один gather по таблице (32×256), MDS — n gather’ов + XOR-накопление, ARX — нативная uint64-арифметика; всё векторизуется по блокам на NumPy (CPU) или CuPy (GPU), workers>1 добавляет межпроцессное масштабирование (на Linux/fork расписание наследуется воркерами без перестроения). Результат побитово идентичен одиночному пути — проверяется самопроверкой.

§13Kazual-64: учебная версия и ручной пример

У Kazual-512 есть «сын»: Kazual-64 — тот же шифр, уменьшенный до размера, который можно посчитать вручную. Каркас и компоненты идентичны один-в-один: та же схема Лай–Мэсси, те же три S-box’а, та же динамическая Cauchy-MDS, та же Заслонка, та же Несущая с тем же чередованием спариваний фаз, тот же Веер, тот же тип расписания ключей с полноценной внутренней ветвевой MDS. Отличия только количественные — размеры: изучив Kazual-64, человек понимает Kazual-512 автоматически. Все числа ниже получены запуском кода.

Kazual-64 не предназначена для защиты данных. 64-битные блок и ключ дают потолки 2³² (неотличимость) и 2⁶⁴ (перебор), а число раундов сокращено ради ручного счёта. Это учебный инструмент; «младший брат» Kazual-Micro (16-битная F) — тем более: он существует только для полных переборов в самопроверке.
